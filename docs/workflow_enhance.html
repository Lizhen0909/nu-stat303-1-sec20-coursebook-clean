3  From Notebook to HTML with Quarto

You will write assignment code and explanations in a VS Code Jupyter notebook, then use Quarto to generate the HTML file for submission. This chapter completes that workflow.

3.1 Install and Verify Quarto

Install the Quarto application from the official download page. Quarto is separate from Python; installing a similarly named Python package or a VS Code extension is not a substitute for the application.

Open a new VS Code terminal after installation and run:

quarto --version

This command can run from any folder. A version number confirms that the terminal can find Quarto. If the command is not found, restart VS Code so it sees the updated PATH, then check the installer instructions before editing PATH manually. The optional Quarto VS Code extension can help with authoring, but the terminal command is the workflow used here.

3.2 Use the Notebook Template

The setup practice kit includes activity03.ipynb and setup_assignment.ipynb. Each begins with a Raw cell containing Quarto’s YAML settings:

---
title: "Setup Practice"
author: "Your Name"
format:
  html:
    embed-resources: true
    toc: true
    code-fold: false
---

Edit the title and author inside the existing Raw cell. Keep its --- delimiters and indentation, and do not run this cell as Python. If your editor does not offer a Raw-cell control, retain the cell in the supplied template rather than recreating it as a code cell.

embed-resources: true embeds ordinary figures, styles, and scripts into the HTML. It does not package your Python environment or the input CSV for rerunning the analysis, and external websites or live services can still require internet access. code-fold: false keeps code visible for review.

3.3 Write a Readable Notebook

Use Markdown headings to organize answers. Describe what a result means near the code and output that support it. Remove temporary installation cells and irrelevant exploratory output before submission. Keep required imports and computations in a runnable order.

The supplied plotting and data-reading code is a workflow demonstration. You will learn these libraries in later chapters; here the goal is to run it in the right environment and verify its output.

3.4 Run, Save, and Render

Quarto normally uses an .ipynb file’s saved outputs; it does not rerun its code by default. A successful render therefore does not prove the notebook ran correctly or contains current results.

Before rendering:

  1. Select the intended .venv kernel.
  2. Restart the kernel and run all code cells from top to bottom.
  3. Resolve unexpected errors and check that figures appear.
  4. Save the notebook.

Terminal, starting in stat303-setup: first list files and verify that activity03.ipynb is present. Then run:

quarto render activity03.ipynb --to html

For this standalone practice kit, the output should be activity03.html beside the notebook. The kit deliberately has no _quarto.yml project configuration that would redirect the output elsewhere.

If a filename contains spaces, quote it:

quarto render "my assignment.ipynb" --to html

The working directory determines how the terminal locates the notebook. It does not automatically change the directory in an existing notebook kernel. Quarto has an optional --execute flag for rerunning code during rendering; we use explicit notebook execution and saving as the main submission workflow.

3.5 Inspect the HTML Before Submitting

Open the generated .html in a web browser. Check the title, author, explanations, code, tabular output, and figure. Look for missing outputs, stale results, raw YAML accidentally displayed as text, or unexpected error messages.

Copy only the HTML into a separate folder and open that copy. Ordinary plots and formatting should still appear. For this kit, disconnecting from the internet provides an additional check that the displayed report is not relying on online assets. This check concerns viewing the report, not rerunning its Python code.

Save the source notebook and input data for your own reproducible work. The integrated assignment below asks for the HTML; any additional course-platform instructions take precedence.

3.6 Troubleshooting by Symptom

Symptom Check before changing anything
ModuleNotFoundError Notebook sys.executable versus the Python used for installation
FileNotFoundError Notebook Path.cwd(), resolved path, spelling, case, and extraction layout
No valid input files for Quarto Terminal location and the notebook’s exact filename
Quarto command not found Quarto application installation and a fresh terminal/VS Code session
Missing or stale HTML outputs Restart/run all, save the notebook, render again, open the latest HTML
HTML needs a companion folder Raw-cell YAML includes embed-resources: true; render again

3.7 Practice Activity: A Report That Travels

Goal: Render and inspect a single-file report. File: activity03.ipynb; use the same .venv and data/ folder from Chapter 2.

  1. Edit the template title and author in its Raw cell.
  2. Run the provided code to locate the CSV, display the data, and produce a small plot. Explain in Markdown what appears on the plot’s two axes.
  3. Restart, run all, and save. Confirm the notebook still works in order.
  4. In the terminal, show your current directory and verify the notebook is there. Render it with Quarto.
  5. Open activity03.html. Find your title, name, explanation, code, and figure.
  6. Copy the HTML alone into a separate folder and open the copy. Check that its figure and formatting still display.
  7. Add a short verification note to your notebook stating what you checked, then save and render again. Repeat the viewing check on the final HTML.

Completion checks: Quarto reports an output file, the final HTML contains your explanation and plot, and the standalone copy is readable. You can explain why an unsaved notebook edit will not appear in the generated file.

Keep: activity03.ipynb and its final activity03.html.

NoteSelf-check

The CSV has six stations. The demonstration plot shows station IDs on the horizontal axis and temperature in degrees Celsius on the vertical axis. If the plot appears in the notebook but not the HTML, first check that you saved after executing and opened the newly rendered file.

3.8 Integrated Assignment: From Project Folder to Submission

Purpose: Demonstrate the complete workflow from all three chapters. Use setup_assignment.ipynb from the practice kit. The small dataset is supplied so the assessment focuses on setup, organization, and verification rather than unfamiliar data-analysis syntax.

Deliverable: One HTML file named setup_assignment.html. Keep the corresponding notebook, CSV, and requirements.txt locally. Do not submit .venv; it is recreated from environment information, not shared as a folder. Follow any additional instructions supplied by your instructor on the course platform.

3.8.1 Part A: Establish Your Workspace

Open the extracted folder in VS Code. Add your name and an appropriate report title. Use Markdown to explain the roles of VS Code, the notebook, its kernel, the terminal, and Quarto in your own workflow.

3.8.2 Part B: Verify Your Python and Packages

Select the course .venv. Demonstrate that the supplied package imports work and include Python and package version information. Record:

  • The terminal shell you used.
  • The command used to identify terminal Python.
  • How you compared it with notebook Python.
  • One package-installation command for the terminal and one for a notebook, explaining which environment each targets.

You may redact your personal username from paths in the submitted report; retain enough of the path to show which environment and project location you checked. A kernel label or prompt alone is not sufficient evidence.

3.8.3 Part C: Locate and Read the Data

Use pathlib and the supplied relative path to data/station_readings.csv. Show a successful file check before loading it. Explain what your relative path is relative to, and how you would diagnose a false file check without moving or deleting data.

Use the provided Pandas code to display the six records and calculate their mean temperature. Explain why changing directories in the terminal does not necessarily change the notebook’s working directory.

3.8.4 Part D: Produce a Readable Result

Run the supplied plotting code. Give the figure an informative title and labeled axes, and add a short Markdown interpretation. The supplied temperatures are illustrative; do not generalize them to a real population or weather pattern.

3.8.5 Part E: Record and Test the Workflow

Export requirements.txt with the project Python from the correct terminal directory. State where the file was created and what it records. Document one troubleshooting check you performed—such as testing an intentionally incorrect path with .is_file()—including the observation and correction. You do not need to break or delete anything.

Restart the kernel, run all, save, render with Quarto, and inspect the HTML. Copy the HTML alone to a different folder and check it there. Include a short final verification statement in the report, save, and render again so that statement appears in the deliverable.

3.8.6 Completion Criteria

Criterion Evidence in the HTML
Notebook workflow Clear Markdown sections, named author, and saved results
Environment verification Python/package information and explanation of the kernel–terminal comparison
Package installation Correctly distinguished terminal and notebook commands
File-path reasoning Relative path, successful file check, and working-directory explanation
Results Six records, calculated mean, labeled plot, and a restrained interpretation
Reproducibility Requirements-file location, troubleshooting record, and fresh-run check
Submission quality Readable single-file HTML with the figure and final verification note

These criteria describe what to demonstrate; grading weights and deadlines are set by the instructor. Environment paths and installed versions will differ across machines. Correct verification matters more than matching someone else’s screenshot.
