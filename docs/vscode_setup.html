1  Jupyter Notebooks in VS Code

In STAT 201, you used Jupyter notebooks through Anaconda. In STAT 303-1, you will continue writing .ipynb notebooks, now inside VS Code, and use Quarto to produce HTML assignment submissions.

By the end of this chapter, you should be able to:

  • Open a project folder.
  • Run and save a notebook.
  • Identify its Python kernel.
  • Explain the roles of the tools you use.

1.1 Anaconda vs. VS Code

Anaconda and Visual Studio Code serve different roles and can be used together. Anaconda provides Python, packages, and environment-management tools; VS Code provides a flexible workspace for writing code and managing projects.

Anaconda Visual Studio Code (VS Code)

What it is A distribution that includes Python, many common packages, and tools such as conda and Navigator A free code editor from Microsoft, built on the open-source Code - OSS project

Limitations The distribution and environment-management tools are not themselves a code editor; coding takes place in an application such as Jupyter, Spyder, or VS Code Does not include Python or data science packages; install Python separately, for example through Anaconda or python.org, and add the needed extensions and packages

Why we use VS Code in STAT 303-1: You will work with notebooks, local data files, project environments, and HTML reports. VS Code brings the notebook editor, file explorer, and terminal into one workspace, helping you move from writing code to running Quarto for assignment submission. Its coding and debugging tools will also help as you begin using unfamiliar data science libraries.

You can keep your existing Anaconda installation and select its Python environment in VS Code. You will continue using the same .ipynb notebook format from STAT 201.

1.2 Know Your Tools

With Anaconda and VS Code’s roles established, let’s distinguish the other tools you will use.

Tool Its role in this course
Python Executes your Python code
Jupyter notebook A document containing code, Markdown, and saved outputs
Kernel The running process that executes a notebook’s code
Terminal A place to issue commands to a shell such as PowerShell, zsh, or Bash
Quarto Converts your saved notebook into a formatted HTML document

Selecting a notebook kernel is not the same as opening a terminal. Each can use a different Python environment; you will learn to check both.

1.3 Check Your Existing Setup

Already have VS Code? Open it and verify that the Python and Jupyter extensions from Microsoft are installed and enabled. Continue to the practice-folder step below.

Need VS Code? Install it from the official website, then open the Extensions panel and install Microsoft’s Python and Jupyter extensions. On Windows/Linux the shortcut is Ctrl+Shift+X; on macOS it is Cmd+Shift+X.

First look for your existing Python installation, including one supplied by Anaconda. Do not install another Python simply because you are changing editors. If no working interpreter is available, use the instructor’s supported Python version and the official Python installer, or ask for setup assistance.

1.4 Open a Project Folder

Download the setup practice kit, extract it, and open the extracted stat303-setup folder using File → Open Folder. Do not work inside the ZIP viewer or open only a notebook without its surrounding folder.

The same kit supports all three chapters and the final assignment:

stat303-setup/
├── activity01.ipynb
├── activity02.ipynb
├── activity03.ipynb
├── setup_assignment.ipynb
├── data/
│   └── station_readings.csv
└── README.md

You will create .venv/ and requirements.txt in Chapter 2. Keep the notebooks alongside data/ while learning this workflow. This makes the expected working directory explicit; later assignments may use other layouts.

Find these areas in VS Code:

  • Explorer: project folders and files.
  • Notebook editor: code and Markdown cells.
  • Kernel picker: usually at the top right of the notebook.
  • Terminal panel: open it with Terminal → New Terminal; note the shell shown in its tab/menu.

1.5 Select a Kernel and Run a Cell

Open activity01.ipynb. Use its kernel picker to choose an existing Python environment you recognize from STAT 201. Labels vary with installed extensions; a route such as Select Another Kernel → Python Environments may be available. For this first check, your existing environment is sufficient. Chapter 2 establishes a separate course environment.

Run this in a notebook code cell, not the terminal:

import sys
print("Notebook is running")
print(sys.version)
print(sys.executable)

The executable path identifies the Python used by this notebook. A kernel name such as Python 3 is not enough to distinguish multiple installations.

If VS Code reports that ipykernel is required, install it for the selected environment using the VS Code prompt. If that environment is managed or read-only, ask for assistance or follow Chapter 2 to create your own environment; do not install into an arbitrary system interpreter.

1.6 Code, Markdown, and Saved Outputs

Use code cells for computation and Markdown cells for explanations, headings, and answers. Run cells with their play controls or Shift+Enter. Save the notebook with Ctrl+S or Cmd+S.

A notebook remembers values from previously executed cells. Moving or editing a cell does not undo its earlier effects. Before considering work complete, restart the kernel, run all code cells in order, and save again. A successfully executed notebook should not depend on variables created in deleted cells.

The HTML submitted later will be generated from this saved notebook. Writing an explanation in a code comment is useful, but Markdown is better for the report’s narrative.

1.7 If Something Does Not Work

Symptom First check
No kernel is offered Python/Jupyter extensions are enabled; a Python interpreter is installed and discoverable
Code will not run The cell is Code rather than Markdown and a kernel is selected
Output differs after restarting All required assignments/imports occur earlier in the notebook
You cannot find the data folder The ZIP is extracted and the correct project folder is open

1.8 Practice Activity: Your First VS Code Notebook

Goal: Demonstrate that you can use a familiar notebook in the new editor. File: activity01.ipynb from the practice kit. No data science package installation is required for this activity.

  1. Open the extracted project folder and select your intended kernel.
  2. Replace the notebook’s name placeholder with your name in Markdown.
  3. Run the supplied environment-information cell. Add a Markdown sentence identifying which Python installation you selected.
  4. Add a code cell that defines three numerical readings in a list and prints their mean using sum() and len().
  5. Add a Markdown explanation of what the code does. Explain the difference between a notebook and its kernel.
  6. Restart the kernel, run all cells, save, close the notebook, and reopen it.

Completion checks: Your name and explanation render as text, the calculation produces a visible result, and the outputs remain present after reopening. You can point to Explorer, the kernel picker, and the terminal without confusing their roles.

Keep: the saved activity01.ipynb for the next chapters. This is practice; the integrated assignment at the end of Chapter 3 specifies the HTML deliverable.

NoteSelf-check

For readings [18, 20, 22], the mean is 20.0. The notebook is the document; the kernel is the process running its code. Existing outputs can remain visible even when the kernel has stopped, so visible output alone does not establish that a fresh run works.
